# Новая студия за 6 минут

Код не меняется. Студия = папка `tenants/<slug>/` с `business.json` и картинками.
Ранее опубликованные студии продолжают работать: у каждой свой `tenant_id`, свой адрес `/s/<slug>/`,
свой манифест, иконки и service worker.

| Минута | Что делаете | Команда |
|---|---|---|
| 0–1 | Создать папку из шаблона | `pnpm tenant:new polish-gomel --name "Полироль" --owner owner@mail.by --phone "+375 29 123-45-67" --address "г. Гомель, ул. …" --kind "Детейлинг · Гомель" --accent "#22C55E"` |
| 1–3 | Заполнить `tenants/polish-gomel/business.json`: посты, услуги с ценами в BYN и длительностью в минутах, часы приёма, три карточки | редактор |
| 3–4 | Положить фото: `images/hero.jpg` (от 1600 px), `images/logo.png` (квадрат от 512 px), работы `images/work-*.jpg` и прописать пути | — |
| 4–5 | Проверить | `pnpm tenant:validate polish-gomel` |
| 5–6 | Опубликовать образец и собрать оболочку | `pnpm tenant:publish polish-gomel && git add tenants/polish-gomel && git commit -m "Студия polish-gomel" && git push`, через 1–2 минуты `pnpm tenant:verify polish-gomel` (Vercel публикует push сам) |

`tenant:publish` напечатает ссылку для клиентов, ссылку в кабинет и временный пароль владельца.
Новая студия открывается как **образец (preview)**: на сайте плашка «Образец», записи помечены как демо,
реальные уведомления не отправляются.

## Перевод в рабочий режим (live)

Когда владелец согласен работать:

1. В `business.json` укажите оператора персональных данных (ИП или организация, УНП, юридический адрес, почта),
   настоящий телефон и фото. Или владелец заполнит это в кабинете: «Настройки → Студия».
2. `pnpm tenant:validate polish-gomel --live` — покажет, чего не хватает.
3. `pnpm tenant:publish polish-gomel --live` — удалит демо-записи и включит live.

## Повторная публикация

- записи клиентов, оплаты, блокировки и фото, загруженные владельцем, **сохраняются**;
- тексты, цены и часы, изменённые владельцем в кабинете, не перезаписываются. Перезаписать из файла: `--overwrite`;
- услуги и посты, убранные из файла, не удаляются, а выключаются: на них ссылаются старые записи;
- праздники РБ обновляются на 18 месяцев вперёд, особые дни, добавленные владельцем, остаются.

## Поля business.json

| Поле | Что это |
|---|---|
| `slug` | адрес студии: `/s/<slug>/`, латиница, цифры, дефис |
| `owner.email` | вход владельца в кабинет |
| `profile.name`, `shortName`, `kind`, `tagline`, `description` | тексты на сайте; `shortName` — подпись под иконкой (до 12 символов) |
| `profile.address`, `phone` | контакты; телефон в любом формате +375 |
| `profile.accent` | единственный акцентный цвет интерфейса |
| `profile.cards` | ровно три карточки на главной |
| `profile.booking` | `bufferMin` подготовка поста, `stepMin` шаг (15/30/60), `leadMin` минимум до записи, `cancelHours` онлайн-отмена, `horizonDays` горизонт |
| `profile.legal` | оператор ПД (Закон РБ № 99-З): обязателен для live |
| `resources` | посты/боксы/подъёмники: `key`, `name` |
| `services` | `key`, `name`, `price` (BYN, до копеек), `durationMin` (2 суток = 2880), `resources` — на каких постах можно |
| `hours` | часы приёма машин по дням недели; `null` — выходной |
| `holidays` | государственные праздники РБ выходными (по умолчанию да) |
| `exceptions` | особые дни: закрыто или другие часы |
| `works` | фото работ с подписями |
| `demo.bookings` | демо-записи для образца: смещение в днях, время, статус, оплаты |
